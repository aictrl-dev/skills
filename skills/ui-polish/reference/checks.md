# Measured checks

What `scripts/measure.cjs` measures, the threshold, why it matters, and the usual fix. Thresholds live at the top of the script (`TH`); change them there, not per run.

| Check | Severity | Threshold | Why it matters | Usual fix |
|---|---|---|---|---|
| `column-alignment` | error | Fields in the same column of consecutive rows start within 2px of each other | Misaligned columns read as untidy even when nobody can say why | A grid with fixed column tracks (`display: grid; grid-template-columns: 1fr 1fr`), labels above fields, no trailing text inside the row |
| `equal-widths` | warn | Repeated fields differ by at most 2px | Unequal boxes for equal inputs look accidental | Let the grid size the fields (`width: 100%` inside equal tracks) |
| `field-fill` (phone) | warn | A row of fields spans at least 75% of its column | Small boxes on a phone look unfinished and are harder to hit | Full-width fields inside the column; two per row for paired values |
| `accessible-name` | error | Every field has a label, `aria-label` or `aria-labelledby` | Screen readers announce unnamed fields as "edit text", so paired fields become indistinguishable | `<label for>` above each field, or `aria-labelledby` pointing at the question and the unit |
| `label-after-field` | warn | No short label sits to the right of a field on the same line | Trailing units shift columns and are read after the value | Label above the field ("Feet"), or a unit suffix inside the field's right edge |
| `tap-target` (phone) | error when the smaller side is below 24px, else warn | Controls at least 44×44px. A checkbox or radio can use its label's box (see below); a link inside a sentence is exempt | Small targets cause mis-taps, worst for text-link buttons | Pad the control, or turn a text link that switches a mode into a segmented control; for a checkbox, make the label that wraps it 44px tall |
| `input-font-size` (phone) | warn | Field text at least 16px | iOS Safari zooms the page when a smaller field is focused | `font-size: 16px` (or larger) on inputs |
| `text-size` | warn; info for eyebrow labels | No text below 14px; one finding per viewport listing each size and style group | Small text is hard to read on phones and for older users | Move helper text to 14px at least; change the token once, not every use |
| `contrast` | error | WCAG AA: 4.5:1 for text, 3:1 for large text | Low-contrast links and hints disappear | Darken the text colour; do not rely on underline alone for a link |
| `type-scale` (form profile) | info | At most 6 distinct font sizes | Too many sizes flatten the hierarchy | Map sizes onto the project's type scale |
| `overflow` | error | Nothing extends past the viewport | Sideways scroll breaks the page on phones | Remove fixed widths; `min-width: 0` on flex and grid children; wrap long rows |
| `heading` | warn; info when the heading is just outside the scope | A visible heading in the content | The question should be the page's heading, for scanning and for screen readers | Make the main question an `h1` (or the step's single heading) |
| `action-distance` (form profile) | warn | The primary action is at most 25% of the viewport height below the last field | A far-away Next reads as disconnected and makes the step feel longer | Place the action right after the fields; pin it to the bottom only on long, scrolling steps |
| `action-below-fold` (form profile) | error | The primary action is on the first screen when the fields are | The user fills everything and then has to hunt for Next | Remove forced full-height layouts (`min-height: 100vh` with `justify-content: space-between`) |
| `dead-space` (form profile) | warn | No empty band inside the content larger than 30% of the viewport height above the action (see below for what counts as content) | Large empty areas mid-form look broken | Same as above; use the space for the reason you ask, or nothing |
| `invented-number` (compare) | error | No number in new copy outside `[brackets]` | Step counts, times and doses the screen never stated are the most common invented facts | Put the number in a bracketed placeholder for the owner, or remove it |

## How the checks decide

- **Hidden elements are skipped.** Tap targets, text size, contrast and form fields ignore what is in the DOM but not on screen: an element clipped away entirely (`clip: rect()` with no area, or `clip-path: inset()` whose opposite insets cover the whole box, such as `inset(50%)`; `inset(50% 0 0 0)` still shows half and is measured), an element of 1px or less that is clipped or has `overflow: hidden` (the sr-only / visually-hidden pattern), an element entirely off-screen (for example `left: -9999px`), and a `tabindex="-1"` control inside a zero-size clipping wrapper (the usual spam honeypot). `aria-hidden="true"` does not count: it hides content from screen readers, not from the eye, so visible `aria-hidden` text and controls are measured.
- **Hidden copy still counts for `--compare`.** The copy list includes sr-only and `aria-hidden` text and every `placeholder` and `aria-label`, so a number added only in hidden copy still fails `invented-number`.
- **A checkbox or radio label can be the target.** Tapping a label toggles its control. A label that wraps the control is the target; a separate `label[for]` counts when its box is within 12px (`TH.labelGapPx`) of the control's, as in the usual flex row with a small gap. The target is then the larger of the two boxes on its own, never their bounding union, so the gap itself never counts: a 20px-tall label 10px below a 20px checkbox leaves it an error, and so does a `display: contents` label (it has no box). A 20px checkbox in a 44px-tall wrapping label passes; when the label helps but is still short, the message says "its label is a W×Hpx target".
- **Only links in a sentence are exempt** (WCAG 2.5.8 inline exception). The sentence is the link's text container: its parent, or the first inline ancestor with text of its own. It needs at least 2 words and 12 letters outside links, and must not be a list of links with only spaces or punctuation between them. `I agree to the <a>terms</a> and the <a>privacy notice</a>.` is exempt; `Page <a>1</a> <a>2</a> <a>3</a>`, `Sort by: <a>Price</a> <a>Name</a>` and a lone link in a `div` or `li` are measured.
- **Small text is one finding per viewport.** Text below 14px is broken down into groups by rounded size and style token (the nearest class naming a size or text role, such as `.text-small`, `.caption` or `.text-[12px]`, else the tag), for example `17 text runs below 14px: 13px × 12 (.text-small), 12px × 5 (.caption)`. The finding's `groups` field keeps each group's size, signature, count and up to three example selectors.
- **Eyebrow labels are info.** A small run of at most four words with letter-spacing of at least 0.04em is the eyebrow or kicker pattern when it is upper case (`text-transform: uppercase`, or cased letters with no lower-case ones, so uncased scripts such as CJK never qualify) and mostly letters, so prices and dates such as `$49.99 / 12 MO` do not. Step numbers of up to three digits (`01`) are deliberately treated as eyebrow labels too. Eyebrow groups form their own `info` finding per viewport (each group has `eyebrow: true`), so they never raise the warning.
- **A heading just outside the scope counts.** With `--scope` narrower than `main` (a form, a card), there is no warning when a heading labels the scope (or an ancestor) through `aria-labelledby`, or when the nearest heading before it shares an ancestor with the scope other than `body` (it may be `main`, as in `main > h1 + form`) and either ends within one viewport height above the scope's top or sits beside it (overlapping it vertically). Headings in site chrome never count: `nav`, `aside`, the page-level `header` and `footer`, and the banner, navigation, contentinfo and complementary roles. The heading check reports `info` ("Heading is outside the scope") instead.
- **Dead space: what counts as content.** Anything a person sees, not a tag list. An element that shows text of its own counts (a `li`, `span`, `summary`, `dt`/`dd`, `td`/`th`, `figcaption`, `blockquote` or a `div`'s own text), as does a replaced or graphic element (`img`, `svg`, `video`, `canvas`, `iframe`, form controls, buttons). So does a painted box such as a card or chip: an element with a background image, a background colour that differs from its parent's, a visible border or a shadow, that is smaller than 90% of the scope, so wrapper sections do not fill the page. Hidden, zero-size and `position: fixed` elements never count, nor does a box that contains the primary action. `action-distance` is unchanged: it measures from the last field to the action.
- **One cause, one finding.** Fields in the scope that share a font size below 16px are one `input-font-size` finding ("6 fields use 15px text…"), and controls with the same tag, type, classes and short side are one `tap-target` finding. A grouped finding carries `count`, up to three `examples` and every member's selector and anchor in `members`.
- **Identical on both viewports, reported once.** A finding with the same check, severity, element and message on phone and desktop is written once with `viewports: ["phone", "desktop"]`, and the printed counts count it once. For a merged finding, `viewports` is authoritative: `viewport` holds only the first of them, for older readers, so filter on `viewports.includes("desktop")`, not `viewport === "desktop"`.

## Comparing runs

`--compare before.json after.json` expands both files to (viewport, part) pairs before matching, where a part is a member element of a grouped finding or a style group of the small-text finding. Merging viewports or grouping elements is therefore never reported as a fix, and files from older versions still compare. Elements that share an anchor (radios with one `name` and no id or label) stay apart: a repeated anchor falls back to anchor plus selector. Each list counts a finding once however many viewports and parts it covers; when only some parts of a group changed, the line names them ("2 of 3 elements: …"). Small text is matched per style group when both files have groups, so a new small-text style shows as new; against an older file, which has one small-text count per viewport, it is matched per viewport only. Exit 1 when an error is new or remaining, or new copy contains an unbracketed number.

## Profiles

`--profile form` (default) runs every check. `--profile content` is for articles, docs and other long-form pages: it skips `type-scale`, `action-distance`, `action-below-fold` and `dead-space`, which assume a single form step with one primary action.

## Accepted decisions

A finding the owner has decided to keep goes in `ui-polish.config.json`, read from `--config <file>` or the current directory:

```json
{ "ignore": [{ "check": "text-size", "selector": ".eyebrow", "reason": "brand kicker labels, approved by design" }] }
```

A rule matches a finding when `check` is the same (omit it to match any check) and the finding's element, or an ancestor of it, matches `selector` (omit it to match the whole check). Each rule needs a `reason`. Matching findings move from `findings` to `accepted` in `measure.json` with the reason, are printed in an "Accepted" section, do not change the exit code, and are listed separately by `--compare`. A selector that is not valid CSS is reported and never matches. Accepting stays possible for any finding, but the run prints a warning (and lists it in `configWarnings`) when a rule accepts an `error` finding, or when its selector matches the scope root or `body`/`html` and so accepts every finding of its check on the page. A config file that is not valid JSON, whose root is not an object with an `ignore` key (a bare array of rules, or a misspelt key such as `ignores`), or with a rule that has no `reason`, stops the run with exit 2.

## Several targets

`measure.cjs <t1> <t2> … --out dir` writes each target to `dir/<slug>/` (the URL path or file name) and `dir/summary.json`, and prints one rolled-up list. Findings merge when they share a check, a selector with `:nth-of-type` indexes removed (for small text, each size and style group; for grouped findings, the group), and a message with numbers and quoted text blanked; each merged line lists the pages it appears on. Exit codes: 3 if any target failed to load, which wins over 1 if any target has an error finding, else 0; the targets that did load are still written and rolled up. One target writes to `dir/` as before. Each target's notes (config selectors that are not valid CSS, config and `--hide` warnings, scope screenshots that failed) print under its line in both modes. An unknown option (for example `--viewport` for `--viewports`) exits 2 instead of being read as a target.

Limits: the script measures the rendered DOM, not intent. It cannot tell whether a label is the right word, whether the heading says the right thing, or whether the page looks trustworthy; that is the rubric's job. Contrast is skipped on text over images or gradients.
